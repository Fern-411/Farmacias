1. INTRODUCCIÓN Y CONTEXTO DEL PROYECTO

El presente informe aborda el diseño y estructuración formal del patrón arquitectónico Modelo-Vista-Controlador (MVC) para el Sistema Inteligente de Inventario y Predicción (SIIP) de Farmacias Peruanas S.A. (cadena líder nacional que opera las marcas InkaFarma y Mifarma en más de 2,200 locales).

Propósito del Patrón MVC en el SIIP: Desacoplar la experiencia de usuario asíncrona en ventanilla (Vista en React 18) del procesamiento de algoritmos matemáticos críticos (Controlador y Servicios en Java 17 Spring Boot 3 para Haversine < 10 km y semáforo FEFO 90/60/30 días) y de la persistencia relacional transaccional (Modelo en PostgreSQL 16), asegurando alta disponibilidad (99.9%) y respuestas inferiores a 2.0 segundos.

2. PROCEDIMIENTOS DE ESTRUCTURACIÓN DE INICIO A FIN

La estructuración del MVC siguió 5 procedimientos formales de ingeniería de software:

2.1. Análisis de Usuarios y Roles Operativos

Perfil de Usuario Capa en el MVC Interacción en el Flujo de Datos
Químico Farmacéutico (Ventanilla) Capa Vista (UI) Inicia consultas de stock geocercano (< 10 km), registra ventas por dispensación y genera traslados de emergencia.
Administrador Centro Distribución (CD) Vista / Control Recibe alertas predictivas de quiebre, autoriza transferencias en 1 clic y emite Guías de Remisión SUNAT.
Gerencia de Operaciones y Mermas Vista Analítica Monitorea dashboards ejecutivos de rotación y cumplimiento de la meta de -22% en pérdidas por vencidos.
Motor Predictivo / Cron Jobs Capa Servicio Proceso en segundo plano que evalúa el consumo promedio diario ($CPD$) y actualiza lotes FEFO cada 6 horas.

2.2. Desglose de Módulos y Capas del Sistema

  • Capa Vista (V): SPA construida en React 18 con Vite, Tailwind CSS y Recharts para KPIs y reportes tabulares.
  • Capa Controlador (C): Clases @RestController en Java Spring Boot (enrutadas por Spring Cloud API Gateway en puerto 8080) encargadas de recibir peticiones HTTP, validar tokens JWT y retornar DTOs normalizados.
  • Capa Modelo (M): Entidades JPA (@Entity), Repositorios (@Repository) y Servicios de lógica de negocio (@Service) conectados a PostgreSQL 16 con transacciones ACID.

4. FLUJOS DE INFORMACIÓN DE INICIO A FIN (SECUENCIAS EXPLICADAS)

4.1. Flujo 1: Consulta de Inventario Georreferenciado (< 10 km con Haversine)

De dónde inicia, hacia dónde va y cómo termina:

1. [INICIO: VISTA] Químico Farmacéutico digita "Amoxicilina 500mg" en el Buscador React. 2. [CLIENTE -> GATEWAY] Vista envía: GET /api/v1/inventario/cercanos?lat=-12.09&lng=-77.02 3. [GATEWAY -> CONTROL] Gateway valida Token JWT y entrega petición a InventarioController (Puerto 8081). 4. [CONTROL -> SERVICIO] Controlador invoca: HaversineGeoService.buscarStockCercano(). 5. [SERVICIO -> MODELO] Servicio ejecuta consulta mediante InventarioRepository.findStockByMedicamento(). 6. [MODELO -> BD] PostgreSQL ejecuta SELECT indexado recuperando coordenadas GPS de farmacias con stock. 7. [BD -> SERVICIO] Retorna entidades. El servicio calcula distancia geodésica mediante Haversine. 8. [SERVICIO -> CONTROL] Filtra sedes <= 10.0 km, ordena Top 5 más cercanas y transforma a SucursalDto. 9. [CONTROL -> VISTA] Controlador responde JSON con código HTTP 200 OK hacia el navegador. 10.[TÉRMINO: VISTA] React renderiza la Tabla Comparativa con distancia exacta en km y botón de traslado.

4.2. Flujo 2: Evaluación Predictiva de Caducidades FEFO (Meta: -22% de Mermas)

1. [INICIO: TIMER] Cron Job automático se dispara cada 6 horas invocando AlertasController. 2. [CONTROL -> SERVICIO] Controlador solicita evaluación a MotorPredictivoService. 3. [SERVICIO -> MODELO] Servicio consulta LoteRepository.findLotesActivos() en PostgreSQL. 4. [LÓGICA FEFO] Servicio calcula días restantes (vencimiento - hoy) y clasifica en Semáforo: - 🔴 ROJO (<= 30 días): Crítico / Devolución a laboratorio. - 🟠 NARANJA (31-60 días): Alerta / Dispensación prioritaria FEFO en ventanilla. - 🟡 AMARILLO (61-90 días): Atención / Descuento Agora / Monedero. 5. [CÁLCULO MONETARIO] Multiplica cantidad x precio_unitario para obtener "Impacto Financiero en Riesgo S/.". 6. [PERSISTENCIA] Inserta alertas en tabla ALERTA_PREDICTIVA y actualiza semáforo en LOTE. 7. [TÉRMINO: VISTA] React actualiza en tiempo real el Reporte Tabular de Caducidades y Dashboard.

4.3. Flujo 3: Aprobación de Traslado y Emisión de Guía SUNAT con QR

1. [INICIO: VISTA] Administrador de CD hace clic en "Aprobar Traslado" en la interfaz React. 2. [CLIENTE -> GATEWAY] Envía: POST /api/v1/traslados/891/aprobar con cabecera de autenticación. 3. [CONTROL -> SERVICIO] TrasladosController recibe y transfiere a GuiaRemisionService bajo @Transactional. 4. [SERVICIO -> BD] Ejecuta transacción ACID: Reserva stock en origen y actualiza estado a EN_TRANSITO. 5. [GENERACIÓN LEGAL QR] Servicio construye número oficial GR-001-0008492 y genera Hash SHA-256 para QR SUNAT. 6. [PERSISTENCIA MODELO] Inserta comprobante en GUIA_REMISION y hace COMMIT en PostgreSQL. 7. [TÉRMINO: VISTA] Retorna GuiaRemisionDto y React abre el modal oficial de Guía SUNAT para imprimir.

5. CONCLUSIONES

  1. Separación de Responsabilidades: La arquitectura MVC desacoplada garantiza que la lógica matemática de Haversine y FEFO resida en servicios testeables en Java, mientras que la interfaz en React permanece ligera y fluida.
  2. Trazabilidad y Seguridad: Cada transacción cuenta con validación perimetral JWT en el Gateway y persistencia ACID en PostgreSQL, impidiendo inconsistencias de stock en la red de farmacias.
  3. Cumplimiento de Metas: El flujo de información estructurado soporta directamente la reducción del 22% en mermas económicas y asegura la disponibilidad continua de medicamentos críticos.
